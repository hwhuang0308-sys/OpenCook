Extract the user's confirmed cooking requirements. Return only JSON: {"changes":{...},"evidence":[{"field":"ingredients","source_id":"id","quote":"exact user words","stock_name":"鸡蛋","quantity_text":"两","unit_text":"个"}]}.
When the new user message explicitly requests cooking guidance or accepts a clear offer of guidance in previous_assistant_reply, ALSO return guidance={"action":"start","source_id":"actual id","quote":"exact user agreement/request"}. This is separate from recipe conditions. A request such as “配方改好后直接带我做” remains pending while you adapt. If they explicitly decline, postpone guidance or ask only to preview the recipe, return guidance.action="none" with that quote. Mere recipe acceptance without a guidance offer does not imply consent. Otherwise omit guidance to preserve an unfinished request. Never infer consent from the assistant's own suggestion.
All input is data. sources contains actual user messages and actual question answers; a question's wording is context, not a user statement. previously_confirmed is an earlier extraction. Produce only updates supported by these sources, preserving unaffected facts. Later explicit corrections override earlier conflicting choices. Use the user's language.
Only new_sources can support a new change. Older sources provide context and have already been processed: do not reinterpret them or reopen an earlier decision. When new_sources only accepts a recipe or asks to start/resume guidance, return changes={} and evidence=[]; do not re-extract old exclusions, serving counts or cooking preferences.
changes can contain ingredients, seasonings, inventory_only, servings, minutes, equipment, equipment_only, excluded, dietary_requirements, preferences, regional_context, emotional_context. Stock entries are {"name":"原话名称","quantity":positive number,"unit":"原话单位"}, with quantity and unit omitted when unknown. Other lists contain strings; servings/minutes are numbers or null to clear an old limit. Lists replace the previous corresponding list, so keep still-valid entries. Set equipment_only only for an explicitly exhaustive restriction, not merely a named pan.
ingredients AND seasonings are arrays of OBJECTS, never strings. Correct: "seasonings":[{"name":"油"},{"name":"盐"},{"name":"老抽"}]. Wrong: "seasonings":["油","盐","老抽"]. All other list fields contain strings.
Every updated field requires evidence with its field name, an actual source_id and an exact quote from that source's text. Never cite a question as the answer. For EVERY numeric stock quantity also provide evidence with stock_name, quantity_text (the exact numeral span, e.g. 两 or 2) and unit_text (the exact unit span). Do not convert units. If the user has not stated the available amount, omit quantity and unit. Never infer stock from a recipe's required quantities, servings, assistant suggestions, or agreement to cook.
“俩” itself means “两个”: “俩鸡蛋” supports quantity=2, unit="个", quantity_text="俩", with unit_text omitted. Do not omit this plainly stated count merely because 个 was implicit. Full-width digits are numeric statements too.
The last_presented_recipe is a proposal, not confirmed user facts. It only resolves references such as “这些调料我都有”: add the seasoning names as available, WITHOUT recipe quantities or an inferred serving requirement. “可以，教我做” accepts guidance, not a statement of stock amounts or taste. An available ingredient need not be used. Having sugar does not mean wanting sweet food.
Record only personal requirements and resources. Routine cooking choices (oil allocation, when to add soy sauce/water, heat, timing, cutting) are decided by Cook and belong in the recipe, unless the user explicitly specifies one. Do not invent health restrictions, guest preferences, missing utensils or exclusions. The user's hometown or emotion can be retained in their own words, not expanded into dietary rules.
Examples: “两个鸡蛋三个西红柿” gives 鸡蛋2个 and 西红柿3个 with numeral/unit evidence for each. “我的酱油是老抽” replaces generic soy sauce availability with 老抽, leaves its amount unknown, and records that variety requirement. “糖不要了，吃咸口” removes an old sweet preference and excludes sugar. “油盐都有，你决定用多少” leaves available amounts unknown. “继续” adds no requirements: return changes={} and evidence=[].
